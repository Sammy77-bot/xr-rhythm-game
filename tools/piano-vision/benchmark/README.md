# 钢琴识别评测集 v0.1

本地试验包含一段 B 站第一人称视频（约 22 秒）及两段 PianoVAM 固定俯拍（共约 96 秒）。两段俯拍各有视频、录音、实录 MIDI 导出的音符表和键盘四角参考点。B 站来源与其他待测候选记录在 [候选清单](bilibili-candidates.json)，按视频及分 P 管理。

## B 站第一人称压力测试

以 2 秒为间隔抽取 11 帧。人工确认开头有明显运动模糊，后续帧中琴键两端多次出画，双手与谱页间歇遮挡琴键。KeyNet 在彩色和灰度输入上均为 **0/11 帧成功定位**。评测记录的是模型是否输出琴键，画面没有完整键盘，未给这段视频算 88 键准确率。[原视频](https://www.bilibili.com/video/BV1dT4y1T7bj/)

Basic Pitch 从该视频音轨输出了 110 个候选起音，保存在 [未验证的音符结果](results/BV1dT4y1T7bj-notes-unverified.json)。这段没有同步 MIDI，候选音符还未逐条核对，因此未报告弹奏准确率。

## 一个八度的局部定位原型

第 10 秒人工标定一次。选同一组 C–B 白键，从 C 的左边和 B 的右边各取前、后两个端点。四角约束图像里的琴面区域。预览把这个平面沿宽度划为七个白键，作为引导位置的初步验证。黑键高度、绝对八度和三维位姿分别需要额外数据。

OpenCV 从首帧的区域中选出 36 个角点，用金字塔 Lucas–Kanade 追踪，按往返一致性和 RANSAC 剔除不可靠点。每次与标定帧重新匹配，使用上一帧变换作为初值。特征不足、区域变形过大或出画时返回定位丢失。后续自动初始化可以利用五个黑键的两组间距特征，再估计两端白键边界。[OpenCV 光流](https://docs.opencv.org/doc/doxygen/html/dc/d6b/group__video__track.html) · [CLAVISION 键盘分割研究](https://opus.uleth.ca/bitstreams/a80e7dd0-cf94-4c46-be1b-638a26d6467e/download)

| 指标 | 结果 |
| --- | --- |
| 第 10–21.5 秒，标定后的跟踪输出 | 345/345 帧 |
| 第 12、14、16、18、20 秒，人工复核 | 5/5 有输出，四角平均误差的中位数 1.95 像素，约 0.11 个白键宽 |
| 单线程 CPU 每帧处理，360 × 480 | 中位数 1.39 ms，P95 1.84 ms |
| 注入 10 张全黑帧 | 10/10 拒绝输出，恢复到标定画面后可重新定位 |

像素误差依据人工标点估计，尚未逐帧标注。该结果适用于一段人工初始化的可见区间，暂未测无初值搜索、大角度转头、重新入画及眼镜端到端延迟。处理计时包含灰度转换与跟踪，采集、视频解码、显示均在计时之外。与前面的整琴识别分开计分。

速度参照。旧 KeyNet 用同一视频第 12、14、16、18、20 秒的五张彩色画面独立定位，预热后记录浏览器 50 次模型调用（10 次全图搜索和 40 次候选区域计算），耗时中位数为 29 ms。五张都未输出整琴定位。这个耗时对照反映整琴搜索和已有局部区域跟踪的工作量差异。

运行 `python track_octave.py labels/BV1dT4y1T7bj-octave.json media/BV1dT4y1T7bj.mp4 results/BV1dT4y1T7bj-octave.json --preview media/BV1dT4y1T7bj-octave-preview.mp4` 可复现。Python 需要 OpenCV 和 NumPy。预览视频含原片画面，仅留本地。

## 扩展到相邻两个八度

两段各自用局部特征跟踪，预览覆盖 14 个白键位置。低音区用第 7.2 秒标定，高音区沿用第 10 秒的标定。两段同时输出时，检查共用键边的前、后端点。如果任一端点的偏差超过约三分之一白键宽，隐藏低音区并保留上次通过的跟踪初值。如果两段一致，低音区的共用边贴到高音区的边界。只剩一段有效时继续显示该段。

- 同一段第 10–21.5 秒，双区同时输出 **287/345 帧**，其余 **58 帧**保留高音区。
- 共用边检查拦下 **42 次**低音区错位输出。低音区还没有逐帧的独立角点真值，输出帧数用于统计覆盖率。
- 360 × 480 单线程 CPU 处理耗时中位数 **3.10 ms**，P95 **3.59 ms**。包含两段光流与共用边检查，采集、解码和显示在计时之外。原单八度配置复测仍为 345/345 帧。

## 双八度听音回放

取 PianoVAM 测试段 3–16.5 秒，手工标定两个相邻八度的起始键 C3（48）和 C4（60）。Basic Pitch 从独立音轨推断音名、起音与结束时间，回放用这些事件在跟踪到的区域内点亮对应键位。区域外的音保留音名，定位丢失时取消该区域亮键。黑键高亮采用模板近似投影。

网页麦克风单音识别用同一录音中 74 个互不重叠、足够长的单音窗口与实录 MIDI 对比，69 个音高一致。窗口由参考音符时间定位，成绩只衡量给定窗口的音高识别。浏览器模拟麦克风另验证了 C4 白键、F♯4 黑键和静音清除。

复跑时先用 `score_notes.py` 生成包含 `end_s` 的音符结果，再向 `track_octave.py` 传入 `--notes results/2024-09-04_17-07-59-notes.json` 和 `--preview`。用 FFmpeg 从第 3 秒截取原音轨，与输出画面合成。

## 88 键听音回放

用现有的 PianoVAM 22.8 秒俯拍验证片段。用数据集标注的四角初始化整琴位置，再追踪琴面，将 A0–C8 映射到 52 个白键、36 个黑键。Basic Pitch 从录音提取音高、起音和结束时间，回放按原声同步亮键，重叠的音可以同时高亮。

- 整琴定位在初始化后的 **1344/1365 帧**输出位置。定位丢失时停止画键位。以首帧低音区已有的 12 个手标键位点抽查，模板覆盖了 11 个。黑键轮廓按模板近似，较窄的黑键需要逐键标定才能进一步核对。
- 参考 MIDI 实际演奏范围为 **G2–C6**。对照实录 MIDI，以同音高且起音误差不超过 ±50 ms 匹配，正确 142 音，误报 14 音，漏报 50 音，F1 为 **81.6%**。
- 极端音区用 A0、A♯0、B7、C8 四个合成音做了补测。模型只输出 A♯0，起音约晚 150 ms。全键盘的键位映射已建立，真实钢琴两端的听音效果仍需录音验证。
- 复跑时用 `score_notes.py` 的 `--full-keyboard` 生成音符结果，再用 `track_octave.py` 读取整琴标定，传入 `--notes` 和 `--preview`，将原音轨合到预览。使用固定俯拍录像离线处理。

## 五段新录音的实时听音复测

从 PianoVAM 官方划分选取两段验证录音和三段测试录音，各截取前 45 秒。只用验证录音比较窗口长度和检测阈值。测试录音用于对照。用 48 kHz 单声道因果音频窗，每 28 ms 计算一次，模拟页面连续两次一致才切换音名的逻辑。参考音高及按下、松开时间来自琴的实录 MIDI。起音指标统计按下后 100 ms 内、只有一个键按住的采样时刻。稳定单音指标还要求距起音至少 100 ms，且窗口附近没有其他参考音的持续音。

| 片段 | 用途 | 起音后 100 ms 内正确帧，改前 → 改后 | 稳定单音正确帧，改前 → 改后 |
| --- | --- | --- | --- |
| 2024-09-05_21-31-00 | 调试 | 72 → 118 / 179 | 843 → 850 / 867 |
| 2024-09-05_21-04-38 | 调试 | 113 → 199 / 313 | 713 → 714 / 728 |
| 2024-09-04_17-02-04 | 测试 | 79 → 120 / 175 | 842 → 837 / 884 |
| 2024-09-05_21-26-38 | 测试 | 74 → 128 / 211 | 666 → 667 / 704 |
| 2024-02-15_20-47-59 | 测试，叠音密集 | 0 → 0 / 21 | 30 → 32 / 50 |
| 测试集合计 |  | **37.6% → 60.9%** | **93.9% → 93.8%** |

- **换音**。旧差分窗口偏向较早的样本，短时间内会继续读到前一个音。新版让不同候选周期都用靠近当前时刻的样本对，并缩短到 45 ms 的比较跨度。两段以单音为主的测试片段中，首次显示正确音名的中位数从 68.3 / 75.8 ms 降到 43.3 / 52.5 ms。这是用录音模拟的音符到识别结果时间。
- **八度**。一个调试片段的 A3 原先有 7 个稳定窗口被读为 A4。增加倍周期比较后，这 7 帧恢复。另以 44.1 和 48 kHz 合成高音检查采样点取整造成的假倍周期，加入基频谱能量门槛。测试集中仍有少量低一个八度的误读。
- **弱尾音与泛音**。在测试片段 2024-09-04_17-02-04 的 16.829 秒，参考仍是 G4，分析窗 RMS 已降至约 0.0027，低于静音门槛。20.469 秒的参考 C4 被读成 G5，分析窗的主峰约 790 Hz，接近 C4 的第三泛音。两段现象分别对应漏读和非八度错音。
- **叠音**。密集片段有 955 个采样时刻同时按下多个键，单音识别器只能给一个候选。新版有 353 个时刻命中其中一个音，仍无法输出完整和弦。

数据来自 [PianoVAM 固定版本](https://huggingface.co/datasets/PianoVAM/PianoVAM_v1/tree/408daf63883a7f32366552475794c5cfad657e7a) 的 `Audio/` 和 `TSV/`。算法基于 [YIN 基频估计](https://www.ee.columbia.edu/~dpwe/papers/deChevK02-yin.pdf)。运行 `node score_listening.mjs listening-cases.json results/listening-after.json` 可复跑。逐段统计、错音和示例时间见 [旧版结果](results/listening-before.json) 与 [新版结果](results/listening-after.json)。

## 琴键定位

每段均匀抽取 12 个时间点，每帧用彩色和灰度各跑一次现有 Demo。每张图都独立开始识别，使用当前照片模式的多次投票。测试的是这一帧能否建立定位。

| 片段 | 彩色认全 88 键 | 灰度认全 88 键 | 灰度拟合到任意键盘 |
| --- | ---: | ---: | ---: |
| 22.8 秒，官方验证集 | 10/12 | 11/12 | 11/12 |
| 73.2 秒，官方测试集 | 4/12 | 2/12 | 3/12 |
| 合计 | 14/24 | 13/24 | 14/24 |

每个已拟合样本还计算四个角的平均偏差，以键盘宽度归一。73.2 秒片段有一次灰度误拟合，角点平均偏差达到键盘宽度的 16.8%。四角误差和键数分别列在 [逐帧结果](results/keys.json)。

另外在两段的第 0 秒分别人工标注了最低一个八度的 12 个琴键内点。第一段彩色覆盖了 12/12 个对应键位，灰度覆盖了 11/12 个。第二段彩色未拟合，灰度误拟合为 61 键，两个版本均为 0/12。未拟合帧也计入分母。原始像素坐标和音高保存在 [样本清单](manifest.json) 的 `key_points`。真实眼镜的分辨率、广角、头动及连续追踪需要单独测。

## 弹奏识别

采用项目现有的 Basic Pitch ONNX 钢琴参数，将独立录音转成音符事件。参考值来自实录 MIDI 导出的 TSV。只比较音高和起音，每个预测最多匹配一个同音高的参考事件。

| 片段 | 参考音符 | 正确 / 误报 / 漏报（±50 ms） | 精确率 | 召回率 | F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 22.8 秒 | 192 | 142 / 14 / 50 | 91.0% | 74.0% | 81.6% |
| 73.2 秒 | 99 | 99 / 12 / 0 | 89.2% | 100.0% | 94.3% |
| 合计 | 291 | 241 / 26 / 50 | 90.3% | 82.8% | 86.4% |

音频成绩不包含视频判定按键、手指或指法。逐音预测及 ±100 ms 的对照结果保存在 `results/*-notes.json`。本轮使用同一音频配置处理两段，没有依据测试结果调参。

## 复跑

先启动琴键 Demo。用 FFmpeg 和 Playwright 运行 `node score_keys.cjs manifest.json results/keys.json`。默认读取本机 5275 端口。可通过 `PLAYWRIGHT_MODULE` 指定本机 Playwright 安装位置，通过 `BENCH_BROWSER` 指定浏览器。

PianoVAM 媒体按清单中的 ID 从固定版本的 `Video/<ID>.mp4` 和 `Audio/<ID>.wav` 下载到 `media/`。B 站音轨通过 FFmpeg 从同一视频解码得到。用 `media.sha256` 可核对本次评测的文件。复跑 B 站样本时可在键位脚本末尾追加片段 ID，只评测该片段。

用项目已有的 Basic Pitch ONNX Python 环境执行 `python score_notes.py media/片段.wav labels/片段.tsv results/片段-notes.json`。几何脚本调用现有 Demo 的图片入口和 JSON 导出，音频脚本直接调用现有模型。
